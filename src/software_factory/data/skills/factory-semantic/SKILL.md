# Assess claim and source relationships

Read `factory.json` and [the semantic assistance runbook](../../../.factory/docs/runbooks/semantic-assistance.md). The main orchestrator owns this workflow. The TypeSafe skill teaches API integration; this skill operates the factory's bounded helper. This claim helper is separate from [JEV model routing](../../../.factory/docs/jev-routing.md) and supplies no verification/release authority.

Run `uv run --locked --project .factory software-factory semantic status` from the repository root to inspect local settings. OFF/omitted configuration needs no credentials and yields no advice. Do not enable the feature, change its claim_mode, widen specialist permissions or issue inference merely because this skill was loaded. Existing explicit authorization persists. A status entry must not evaluate anything.

When ON and an eligible claim/source assessment is useful:
1. Identify the research purpose and authorization to send the selected excerpts to TypeSafe. Preserve the complete source packet and review obligations. Do not upload secrets, private transcripts or the whole repository. The helper sends only supplied claim text, selected excerpts and their IDs/locators; it does not retrieve URLs.
2. Prepare bounded atomic claims and sources using the runbook input contract. Hash the exact supplied excerpt, record actual retrieval time and location, and mark incomplete context honestly. Do not refresh timestamps without retrieving the source. Split compound claims when possible.
3. Invoke `uv run --locked --project .factory software-factory semantic check --input .factory/local/claims.json`; add `--mission ID` when assessing an existing mission. Use `--no-network` for a strict bypass. `--no-persist` disables records/cache and works in advisory mode; shadow without persistence skips.
4. Inspect operational status and coverage before any relationships. Exit 2 means unavailable/invalid assistance (provider failure, changed inputs or a busy local lock): the transport already makes at most two bounded retries of transient failures within `deadline_ms`, so do not loop on the command; continue ordinary investigation and review. Missing quote/context, stale sources and service errors do not establish a false claim. Never silently omit unresolved claims.
5. Shadow mode returns only a private report reference and operational metadata, without review states or counts. Keep judgments hidden from baseline authors and reviewers until the baseline is frozen and reviewed. Read the report only for the subsequent independent comparison. This is a workflow boundary, not access control. Do not switch to advisory mode to get around it.
6. In evaluated advisory use, pass annotations alongside the full source packet. Treat supports as support in the supplied excerpts, not truth, current availability, check completion or permission. Confidence is not a correctness guarantee. Each evaluated claim has an advisory `review`: `accepted` at or above `jev.claim_accept_confidence` (default 0.8, per TypeSafe citation-check guidance), otherwise `needs_review`, meaning a human must confirm it against the sources before relying on it. Report needs_review claims explicitly. Neither state is verification, approval or a gate. Resolve conflicts from source evidence; retain independent review.

To check an implementer's key claims about its own change, write `{"schema_version": 1, "claims": [{"id": "C1", "claim": "...", "paths": ["repo/relative/file"]}]}` to `.factory/local/` and run `uv run --locked --project .factory software-factory semantic verify-claims --mission ID --input PATH`. Evidence is only the repository diff since the mission base (no agent text); unchanged cited paths yield `no_evidence` without a request, and excerpts are secret-masked, bounded and hashed in private records. Honor shadow mode the same way. Treat `needs_review`, `contradicts` and `no_evidence` as prompts to inspect the diff, never as approval; results never change mission state, evidence or the gate. See the runbook section on checking implementer claims.

Supported relationships and the versioned rubric live in [resources/claim-support.json](resources/claim-support.json). Other claim operations, prompt hooks and MCP hosting are not implemented. Model selection uses the shared JEV toggle through its separate routing path; claim judgments cannot change task budgets, state transitions or readiness gates. Record unavailable live checks precisely. The helper's local records are not authenticated evidence and must not be promoted into verification or approval records.
