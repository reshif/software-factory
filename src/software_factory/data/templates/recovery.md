# Recovery plan and evidence

## Trigger and affected release

Identify the failed observation, affected artifact/environment and the condition authorizing recovery. Preserve incident evidence.

## Authorized action

Reference the actual standing or specific recovery decision. Describe the exact configured operation and target: flag disablement, artifact rollback, forward repair or explicitly authorized data operation.

## Code and data consequences

State compatibility with current data, irreversible changes, prerequisites and operator responsibilities. Do not assume code rollback undoes migrations.

## Execution and verification

Record external operation references, actual outcomes and post-action health/user-flow checks. Mark attempted recovery separately from verified recovery.

## Follow-up

List unresolved impact, necessary repair work and owner/next action. Restoring the previous version does not establish delivery of the failed feature.
